Диалог с архивом документов: LLM управляет, сервер ищет, считает и проверяет

Как один вопрос пользователя проходит через систему. Модель (Qwen / GLM) только понимает запрос и выбирает операции через Tool Calling / MCP. Поиск, фильтры, таблицы, суммы и проверка ссылок — серверный код на Python и PostgreSQL. Ни одна цифра в ответе не придумана моделью.

LLM — понимает и планируетСервер — выполняет и считаетПроверка
Пользователь

Какие договоры поставки 2024 года содержат неустойку выше 0,1% в день — и на какую сумму они у каждого контрагента?

LLMразбор запроса

Переводит вопрос в план операций — без ответа «из головы»

{"intent": "filter + extract + aggregate",
 "doc_type": "договор поставки", "period": "2024",
 "condition": "неустойка > 0.1% в день",
 "group_by": "контрагент", "metric": "сумма договора"}
Серверhybrid_search

Гибридный поиск: атрибуты + полнотекст + векторы bge-m3

hybrid_search(doc_type="договор поставки", year=2024,
              query="неустойка пени за каждый день просрочки",
              k=200, min_score=0.62)
→ 143 документа, 211 фрагментов с пунктом о неустойке

Атрибуты отсекают лишнее до векторов; порог похожести подбирается на наборе вопросов с ответом и без — ниже порога фрагмент не попадает в выдачу.

Серверextract_terms

Достаёт ставку из текста пункта — правилом, модель только на спорных

extract_terms(fragments, field="penalty_rate_per_day")
→ 128 ставок разобрано правилами («0,2% от суммы … за каждый день»)
→ 9 спорных формулировок → LLM с цитатой → сервер сверяет число с текстом
→ 6 без ставки (пени по ключевой ставке ЦБ) — помечены отдельно
СерверSQL

Фильтр и суммы считает PostgreSQL, а не модель

SELECT counterparty, count(*) AS docs, sum(contract_amount) AS total
FROM   extracted_terms
WHERE  penalty_rate_per_day > 0.001 AND year = 2024
GROUP  BY counterparty ORDER BY total DESC;
→ 37 договоров, 12 контрагентов
Проверкаverify

Каждая строка ответа — со ссылкой на документ и пункт

verify(answer_rows) → 37/37 ссылок открываются, ставка в цитате
                       совпадает с числом в таблице
→ 6 договоров без числовой ставки вынесены в «нужна проверка юристом»

Не совпало — строка не попадает в ответ, система пишет «не нашёл / не уверен», а не догадку.

LLMответ

Пишет ответ только из проверенных данных

Найдено 37 договоров поставки 2024 г. с неустойкой выше 0,1% в день
у 12 контрагентов. Больше всего — ООО «Пример-1»: 6 договоров на 18,4 млн ₽
[Д-2024-0117, п. 7.2] … Таблица и выгрузка в Excel — ниже.
Ещё 6 договоров ставят пени по ключевой ставке ЦБ — их стоит проверить.

Принципы, на которых соберу систему

Модель не считаетЧисла, фильтры и агрегаты — только SQL и Python; модель выбирает инструмент и параметры.
Инструменты — MCP / Tool CallingНебольшой набор операций с понятными схемами: поиск, извлечение, таблица, граф, расчёт, проверка.
Ссылка на источник вездеДокумент, страница, пункт. Нет ссылки — нет строки в ответе.
«Не нашёл» — нормальный ответПорог похожести и проверка цитат вместо уверенной выдумки.
Граф сущностей — для связей«Кто ещё связан с этим контрагентом» — обход графа, а не векторный поиск.
Набор контрольных вопросовВопросы с известным ответом и без ответа — каждое изменение проверяется на них до выкладки.
